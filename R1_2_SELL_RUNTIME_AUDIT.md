## Root cause

**Persistent `ChunkLoadError` / Turbopack stale chunk graph** after `.next` (or Turbopack) artifacts were invalidated while a long-lived `next dev` session (or browser tab) still referenced old `/_next/static/chunks/*` hashes.

### Why the UI looked “stuck on skeleton”

1. Soft navigation to `/sell` shows `app/(platform)/sell/loading.tsx` → `SellSkeleton`.
2. Client never finishes hydrating / mounting `SellPage` because JS chunks 404 / fail to load.
3. Document/API may still return **HTTP 200** (RSC/HTML stream OK) while the **client bundle never mounts** → infinite skeleton + Hydration / `NotFoundError` noise in console.

This is a **runtime/cache** failure, not Sell business logic, Seller Engine, Listing Engine, Upload Engine, Category Engine, Wallet, Drafts, DB, or routes.

---

## Why hydration failed

Client React could not load matching Turbopack chunks for the current server build. Hydration never completed against the streamed Sell markup → browser reported hydration / chunk / DOM errors. Clearing artifacts and restarting forces a **single coherent chunk graph**.

---

## Why chunk loading failed

Browser requested stale hashed paths under `/_next/static/chunks/…` that no longer existed on disk after cache invalidation / concurrent Turbopack rebuild. Classic `ChunkLoadError: Failed to load chunk …`.

---

## Why skeleton remained forever

`loading.tsx` skeleton is the loading UI. It only leaves the tree when the route’s client tree mounts. With chunk load failure, mount never happens → skeleton remains indefinitely despite successful server responses.
